1. Stop both old and new 50TOC services before moving data.
2. Back up the old application's ENTIRE data folder.
3. Extract the new ZIP into a NEW folder. Its default databases are initially empty.
4. Copy the old Jason data folder into the new extracted folder, or point
   FIFTYTOC_DATA_DIR to the existing data directory. Keep live and demo separate.
5. Run START_RESEARCH.cmd for LIVE, START_DEMO.cmd for synthetic demonstration.
   Close any older service using port 8876, then refresh the browser. Verify the
   footer says Core workflow 0.5 and that live mode has no DEMO banner.

Existing Jason 0.1, 0.2 and 0.3 PostgreSQL/PGlite data is retained by additive
migrations. Research, enrichment, corrections, UPC and candidate history remain.
No old targets are fabricated from Research results. Every new target needs
human approval. The older Research Web 1.x SQLite prototype is a separate app
and is not silently imported.

Scavio and Keepa have separate key fields. No key or real database ships in the
ZIP. Encrypted Windows keys can require re-entry under another Windows account.
Session-only keys must be re-entered after service shutdown. Saving a key does
not perform a paid lookup. DEMO disables real key input.

Settings initially use Local manager on this computer. Creating the first
full-access account enables sign-in. Keep the chosen credentials private and
create worker accounts afterward. Workers cannot access manager APIs. Do not
expose this loopback-only test build publicly; shared hosting is a later step.

Read TEST_GUIDE.txt before the first complete test. Live provider calls were not
used during development; fees, eligibility, photos/OCR and live daily source
refresh have explicit verification/integration limitations in README.md.
